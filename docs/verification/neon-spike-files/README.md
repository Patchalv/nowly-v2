# Neon spike files

The working files from the spike recorded in `../neon-spike.md`. The tickets under the "Move Nowly from Supabase to Neon" parent issue build on them. They are prototypes for reference, not part of the app: nothing imports them, and the Neon project they ran against has been deleted.

| File                       | What it is                                                                                                                                                                                                                                                                                                                     | Used by                 |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------- |
| `port-migrations.sh`       | Prints the 14 Supabase migrations as one Neon-ready SQL file: foreign keys moved to `neon_auth."user"`, the `auth.users` trigger removed, broken `$` quoting fixed.                                                                                                                                                            | schema ticket           |
| `neon-additions.sql`       | Applied after the port: drops `handle_new_user`, grants table privileges to `authenticated`, adds `ensure_account()`.                                                                                                                                                                                                          | schema ticket           |
| `production-functions.sql` | Production's hand-edited `update_updated_at`, which the port should adopt, plus a note on the recurring trigger version.                                                                                                                                                                                                       | schema ticket           |
| `fingerprint.sql`          | The query that compares a schema with production, with production's values and the differences to expect on Neon.                                                                                                                                                                                                              | schema ticket           |
| `check-data-api.mjs`       | The 20-check backend test over the Data API (RLS, grants, `ensure_account()`, recurring complete/undo, password minimum, cache-helpers parsing, embedded selects). Needs `NEON_AUTH_URL` and `NEON_DATA_API_URL`, and `@neon/postgrest-js` plus `@supabase-cache-helpers/postgrest-core` installed. Exits non-zero on failure. | schema and swap tickets |
| `cache-key-compare.mjs`    | Shows cache-helpers parses a query from Neon's client exactly as it does from Supabase's.                                                                                                                                                                                                                                      | swap ticket             |
| `lazy-auth.md`             | The lazy `createNeonAuth` getter, the `/api/auth` route and the server-side `token()` probe.                                                                                                                                                                                                                                   | swap ticket             |

The schema ticket asks for a check script with no dependencies. `check-data-api.mjs` uses the Neon and cache-helpers packages, so treat it as the list of checks and expected results, not as the finished script.
